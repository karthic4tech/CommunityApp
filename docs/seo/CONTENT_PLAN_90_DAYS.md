## Editorial rules

- Avoid a standalone page when it would repeat the existing tourism page or lack original, sourced information.
- Use specific official or provider sources and record the date each operational fact was checked.
- Do not invent prices, opening hours, attraction fees, ratings, reviews, availability or contact information.
- Clearly distinguish an enquiry from a confirmed booking.
- English/Tamil versions must be reviewed by fluent local editors; machine/AI translation is not sufficient for sensitive or operational facts.
- Measure discovery and enquiries in Search Console and consented analytics; do not purchase links or fabricate reviews.

## Measurement checkpoints

- **Day 30:** Establish the first Search Console baseline (indexed public URLs, impressions, clicks, CTR and query/page/device breakdown); verify sitemap fetch and inspect rendering. Record enquiry counts from the existing lodging/cab flows if available. Do not compare against invented historic baselines.
- **Day 60:** Compare the latest 28-day window with the first available 28-day window. Identify pages with impressions but weak CTR, queries with relevant impressions, indexing exclusions and enquiry friction. Update content only where sources or user questions support it.
- **Day 90:** Review the full query/page trend, valid indexed pages, Core Web Vitals status, and real enquiry outcomes. Prioritize the next quarter from observed search terms and partner-confirmed lead quality rather than rank guarantees. Use GA4 only after the owner configures a real ID and required consent behavior.
